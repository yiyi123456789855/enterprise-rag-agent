# 面试展示与问答指南

## 90秒项目介绍

我独立实现并部署了一个企业知识库 RAG Agent。系统支持 PDF、DOCX、TXT 和 Markdown 的结构化解析与切片，服务器使用 BGE-M3 生成向量，并将带租户、部门和文档信息的向量写入 Qdrant。查询时先做租户和部门过滤，再执行 Dense 与 BM25 召回、RRF 融合以及可选 CrossEncoder 重排。为了降低幻觉，我增加了证据覆盖门控和引用校验：证据不足或答案没有合法引用时直接拒答。另外实现了连续追问、敏感值与提示注入防护、用户反馈和P95延迟面板，并用固定回归集评估 Recall@K、MRR、回答/拒答准确率和延迟。

## 5分钟现场演示

1. 打开健康状态，说明 BGE-M3、Qdrant、Reranker 和 Generator 配置。
2. 上传复杂企业手册，展示文档状态和切片数量。
3. 询问“连续休假七天需要提前多久申请”，展示答案、引用和Trace。
4. 追问“这种情况下最多能结转几天”，展示 Query 改写。
5. 切换用户部门，展示部门文档无法越权召回。
6. 询问CEO身份证号，再输入提示注入，展示两类安全拒答。
7. 点赞回答，展示反馈和指标变化。

## 高频追问

### 为什么使用混合检索？

语义向量适合处理同义表达，BM25对编号、金额、型号和专有名词更可靠。使用RRF融合可以降低单一检索器的偏差，再让CrossEncoder对少量候选做精排。

### 为什么权限过滤必须前置？

如果先召回再过滤，未授权文本已经进入检索结果甚至模型上下文，可能通过日志、引用或模型输出泄漏。该项目在SQLite候选读取和Qdrant Payload Filter两个层面都执行ACL。

### 如何判断“证据足够”？

门控同时检查最高综合分、问题词覆盖率和关键实体覆盖率。敏感值和提示注入在门控前直接拦截。即使证据通过，生成结果没有合法引用也会被阻断。

### 为什么不用纯大模型判断是否可答？

纯模型判断成本高、波动大，也可能被提示注入影响。确定性门控便于回归测试和解释；后续可以把模型判别作为额外特征，而不是唯一安全边界。

### 当前最大局限是什么？

任务队列仍使用 FastAPI BackgroundTasks，认证还是单个API Key，评测集规模较小。生产化需要 Redis/Celery、JWT/RBAC、PostgreSQL、集中监控和更大的人审数据集。

### 评测结果为什么不能直接代表生产？

当前18条数据来自一份虚构手册，主要用于CI回归。生产结论需要在真实匿名化文档上分层采样，并单独报告BGE-M3和CrossEncoder的准确率与延迟。

## 简历项目描述

**企业知识库 RAG Agent｜独立开发**

- 基于 FastAPI、BGE-M3 与 Qdrant 构建多格式企业知识库，完成结构化切片、向量化入库、SHA-256去重及文档版本管理。
